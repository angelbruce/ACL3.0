### 2.4 关键决策回顾

| 决策 | 选项 | 最终选择 | 原因 |
|------|------|----------|------|
| Embedding 方式 | 完整模型推理 vs 查表 | 查表 | 速度快、无需 GPU、实现简单 |
| Tokenizer | shimmytok vs tokenizers vs 占位 | 占位（字节级） | 先跑通，后续替换 |
| 向量数据库 | Milvus vs pgvector vs Weaviate | Milvus | 高性能、云原生 |
| 构建环境 | Windows 原生 vs Docker | Docker | 避免 C FFI 编译问题 |
| 模型存储 | 打入镜像 vs 外部挂载 | 外部挂载 | 镜像小、更新灵活 |

### 3.3 任务执行顺序与详细计划

#### 第 1-2 天：TASK-013 - 接入 shimmytok tokenizer

**目标**：将占位的字节级分词替换为真正的 shimmytok tokenizer

**详细步骤**：
1. **研究 shimmytok API**（0.5 天）
   - 阅读 shimmytok v0.7.x 源码或文档
   - 理解核心数据结构：BPE、Encoding 等
   - 搞清楚如何从 GGUF 文件加载 tokenizer
   - 写几个小 demo 验证用法

2. **实现 Tokenizer 接入**（1 天）
   - 修改 tokenizer.rs，用 shimmytok 替换字节级实现
   - 实现 `from_file()` - 从 GGUF 文件加载
   - 实现 `encode()` - 文本 → token IDs
   - 实现 `decode()` - token IDs → 文本
   - 获取正确的 vocab_size
   - 确保与 gemma-4-E4B 模型兼容

3. **单元测试验证**（0.5 天）
   - 测试中英文分词效果
   - 测试 encode/decode 可逆性
   - 测试特殊字符、长文本
   - 性能测试（每秒能处理多少 token）

**验收标准**：
- [ ] "你好，世界！" 分词结果合理
- [ ] vocab_size 与模型一致（约 256000）
- [ ] encode → decode 后文本基本一致
- [ ] 单元测试全部通过

**风险与应对**：
- 🔴 风险：shimmytok API 不熟悉，摸索时间长
- 应对：先花半天时间研究 API，写 demo 验证，再正式接入
- 🔴 风险：shimmytok 不支持 gemma 的 tokenizer 格式
- 应对：如果不行，换用 HuggingFace tokenizers crate

#### 第 6-10 天：TASK-022 - 知识边界（5 层可见性）

**目标**：实现企业级知识权限控制，保障知识安全

**详细步骤**：
1. **数据库设计**（1 天）
   - document_boundaries 表：document_id, visibility_level (私有/项目/团队/组织/公开), created_by, created_at
   - boundary_shares 表：id, document_id, target_type (用户/团队/项目), target_id, permissions (view/edit/share), expires_at, created_by, created_at
   - boundary_audit_logs 表（可选）：id, document_id, user_id, action, timestamp, ip

2. **权限模型设计**（1 天）
   - 5 层可见性定义
   - 权限继承规则（项目成员自动可见项目级文档）
   - 越级共享规则（私有文档可共享给指定人）
   - 权限优先级（明确的 + 共享的 = 并集）

3. **用户与项目集成**（1 天）
   - 获取当前用户信息（从 JWT 或请求头）
   - 获取用户的项目列表、团队列表
   - 与现有用户系统、项目系统集成

4. **搜索时的权限过滤**（1.5 天）
   - 搜索前先计算用户可见的文档范围
   - Milvus 搜索时加上过滤条件（project_id 等）
   - 返回结果后再做一次权限校验（双重保障）
   - 不同边界的文档搜索权重可能不同（可选）

5. **文档操作的权限校验**（0.5 天）
   - 查看文档：校验可见性
   - 编辑文档：校验编辑权限
   - 删除文档：校验删除权限
   - 分享文档：校验分享权限

6. **共享管理**（0.5 天）
   - 文档分享给指定用户/团队
   - 设置过期时间
   - 设置权限级别
   - 撤销分享
   - 查看分享列表

7. **API 接口**（0.5 天）
   - 设置文档可见性
   - 管理共享
   - 查看我的权限（哪些文档我能看）

8. **测试**（0.5 天）
   - 各层级可见性测试
   - 越级共享测试
   - 权限继承测试
   - 搜索过滤测试

**验收标准**：
- [ ] 5 个可见性层级都能正确设置
- [ ] 搜索结果自动过滤不可见文档
- [ ] 越级共享功能正常
- [ ] 权限继承正确
- [ ] 低权限用户看不到高权限文档

**依赖**：需要与用户系统、项目系统集成

**风险**：
- 🔴 风险：与现有用户/项目系统集成复杂
- 应对：先定义清晰的接口，M3 阶段先做内置实现，后续再对接真实系统

---

### 4.4 阶段验收标准

- [ ] M2 的所有功能继续保持可用
- [ ] 知识蒸馏：上传文档能提取出摘要和关键词
- [ ] 分类系统：5 个维度分类树正常，文档能打标签
- [ ] 分级系统：5 个维度打分正常，综合评分正确
- [ ] 知识边界：5 层可见性生效，搜索自动过滤
- [ ] 越级共享功能正常
- [ ] 搜索时支持分类/分级/边界的组合筛选

### 4.5 阶段价值

完成 M3 后，vec-svc 就从"一个文档检索工具"升级为"企业级知识管理平台"，具备了：
- ✨ 知识蒸馏：从文档到知识的升华
- 📊 分类分级：让知识有序、可发现
- 🔐 知识边界：企业级安全保障

这正是区别于普通 RAG 系统的核心价值所在。

### 5.4 重点任务说明

#### TASK-025 MinIO 集成
- 保存原始文件（PDF/Word/图片等）
- 数据库只存文本，原始文件在 MinIO
- 支持文件上传、下载、预览
- 按项目分桶或目录

#### TASK-026 异步任务队列
- 大文档处理不能同步阻塞
- 基于数据库的简单队列（先不用 Redis）
- 后台 worker 轮询
- 任务状态：pending/processing/completed/failed
- 进度可查询
- 支持取消和重试

#### TASK-027 知识图谱
- 从文档中提取实体和关系
- 实体识别、关系抽取、实体消歧
- 三元组存储
- 实体详情页（相关文档、相关实体）
- 为幻觉校验提供基础

#### TASK-023 事实支撑校验
- 给定 LLM 回答，拆分为事实陈述
- 每个事实在知识库中搜索支撑证据
- 计算支撑度
- 标记可疑事实
- 给出整体可信度评分

#### TASK-024 图谱一致性校验
- 从回答中提取实体和关系
- 与知识图谱对比
- 检测矛盾点
- 检测缺失知识
